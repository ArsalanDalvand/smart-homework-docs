# راهنمای جامع اساتید و دستیاران آموزشی (TA): طراحی سوال، داوری و مدیریت درس

این راهنما به‌طور کامل نحوه کار با سامانه جامع ارزیابی و یادگیری هوشمند، طراحی سوال با قالب‌های آماده، نوشتن تست‌های داوری خودکار (داکر)، انتشار تمرین‌ها و آزمون‌ها، تصحیح دستی و مدیریت دانشجویان را برای اساتید و تیم‌های دستیاران آموزشی (TA) توضیح می‌دهد.

---

## ۱. آشنایی با ساختار سامانه و نقش‌های تیم TA

در سامانه، هر درس از دو لایه تشکیل شده است:
1. **درس (`Course`):** مخزن کل بانک سوالات، قالب‌های آماده، فایل‌های مشترک استایل و کادر آموزشی.
2. **ترم / دوره ارائه (`Course Instance`):** شامل دانشجویان همان ترم، تمرین‌ها (`HW0`, `HW1`, ...)، کوییزها، دفتر نمرات و بازه انتشار.

### ماتریس دسترسی تیم‌های TA (تب «کادر آموزشی و دسترسی‌ها / Staff»)
دسترسی هر عضو روی دو محور جداگانه تنظیم می‌شود (**محتوای درس** × **داده دانشجویان ترم**):

| نقش / تیم | دسترسی محتوا (`Course`) | دسترسی دانشجو (`Course Instance`) | چه کارهایی می‌تواند انجام دهد؟ |
| :--- | :---: | :---: | :--- |
| **استاد درس** | `Owner` | `Student Data Editor` | مالکیت کامل و مدیریت دسترسی سایر TAها |
| **سرگروه‌های TA** | `Editor` | `Student Data Editor` | بررسی PRها، **همگام‌سازی محتوا (Sync)**، بستن Issueها، مدیریت برچسب‌ها و تمدید ددلاین |
| **تیم طراحی سوال** | `Editor` | `None` *(یا `Viewer`)* | ساخت و ویرایش سوالات، تست‌ها و تمرین‌ها (از پنل یا GitHub) و تست در پیش‌نمایش |
| **تیم تصحیح و مراقبت** | `Previewer` | `Student Data Editor` | تصحیح دستی با Rubric، مدیریت زمان آزمون و ویرایش نمره (بدون ریسک خراب کردن فایل‌های درس) |
| **تیم پشتیبانی / حل تمرین** | `Previewer` *(یا `Viewer`)* | `Student Data Viewer` | مشاهده کد و لاگ ارسال‌های دانشجو برای رفع اشکال (بدون امکان تغییر نمره یا سوال) |

> **ورود یکجای تیم TA:** استاد درس می‌تواند فایل `course-staff-template.csv` را با ایمیل TAها پر کرده و از مسیر **کادر آموزشی و دسترسی‌ها ← Import CSV** همه را یکجا وارد کند.

## ۲. آموزش گام‌به‌گام طراحی سوال (ویژه TAهای طراح سوال)

برای ساخت سوال جدید، **دو روش** دارید: **روش سریع از داخل پنل وب** (برای ساخت سریع و ویرایش‌های کوچک) و **روش حرفه‌ای با GitHub + Pull Request** (پیشنهادی برای تیم‌های چندنفره جهت بازبینی کد و تست‌ها).

### روش الف: ساخت سریع سوال در پنل وب (بدون نیاز به Git)
1. وارد صفحه درس شوید و از منوی راست به **«بانک سوالات درس»** بروید.
2. روی دکمه **«افزودن سوال»** کلیک کنید.
3. **مشخصات سوال** را پر کنید:
   - **عنوان سوال:** عنوان فارسی و خوانا (مثلاً: `برعکس کردن رشته`).
   - **شناسه سوال (`QID`):** فقط حروف انگلیسی کوچک، عدد، `-` و `/` (برای پوشه‌بندی بر اساس سری یا مبحث).
     - **قرارداد نام‌گذاری پیشنهادی:** `s2/reverse-string` برای سری ۲، `s3/sum-digits` برای سری ۳ و... (از نام ترم یا تاریخ در QID استفاده **نکنید**).
4. در بخش **«انتخاب نقطه شروع»** روی گزینه **«قالب‌های همین درس»** کلیک کنید و یکی از قالب‌های آماده درس را انتخاب کنید:
   - **`template/bp-python-stdin-stdout`** ← برای سوالات برنامه‌نویسی با `input()` و `print()` (الگوی ورودی/خروجی استاندارد).
   - **`template/bp-python-pytest`** ← برای سوالات پیاده‌سازی تابع (`def`) با تست‌های `pytest`.
   - **`template/bp-trace-random`** ← برای سوالات مفهومی و ردیابی تصادفی با `server.py` (ضد تقلب).
5. روی **«ایجاد سوال»** بزنید؛ سامانه به‌صورت خودکار فایل‌ها را می‌سازد و روی GitHub کامیت می‌کند.
6. وارد تب **«فایل‌ها و تست‌ها»** شوید، فایل‌های `question.html`، `tests/initial_code.py` و `tests/test_student.py` را ویرایش و **Save** کنید.
7. به تب **«پیش‌نمایش سوال»** بروید، یک بار جواب **صحیح** و یک بار جواب **غلط** ارسال کنید و مطمئن شوید داور دقیقاً نمره ۱۰۰٪ و ۰٪ و پیام خطای خوانا برمی‌گرداند.

---

### روش ب: طراحی سوال با GitHub و Pull Request (پیشنهادی برای تیم‌های بزرگ)
1. مخزن گیت درس را کلون کنید و برای هر سوال یا سری یک شاخه جدید بسازید (`git checkout -b feat/s2-palindrome`).
2. پوشه یکی از قالب‌ها (مثلاً `questions/template/bp-python-stdin-stdout`) را در مسیر جدید (مثلاً `questions/s2/palindrome`) کپی کنید.
3. **قانون طلایی UUID (بسیار مهم):**
   - هر سوال در `info.json` یک `"uuid"` یکتا دارد.
   - هنگام **کپی کردن یک سوال جدید در همان درس**، حتماً یک UUID جدید بسازید (با دستور `uuidgen` یا در پایتون `python3 -c "import uuid; print(uuid.uuid4())"`) و در `info.json` قرار دهید.
   - پس از ساخت سوال، **هرگز UUID آن را تغییر ندهید** (حتی اگر پوشه یا عنوانش را عوض کردید)، وگرنه سوابق پاسخ‌های دانشجویان قطع می‌شود.
4. فایل‌های داخل پوشه سوال را تکمیل کنید:
   ```text
   questions/s2/palindrome/
   ├── info.json              # متادیتا، UUID، مبحث، برچسب‌ها و تنظیم داور داکر
   ├── question.html          # صورت سوال با تم راست‌به‌چپ، جدول نمونه، راهنما و ادیتور کد
   └── tests/
       ├── initial_code.py    # کد اولیه داخل ادیتور دانشجو
       └── test_student.py    # تست‌های عمومی و مرزی داوری خودکار (pytest)
   ```
5. Pull Request باز کنید تا سرگروه TA (Head TA) تست‌ها و حالات مرزی را بررسی و روی شاخه اصلی (`main`) مرج کند.
6. در نهایت، سرگروه TA در پنل درس به منوی راست **«همگام‌سازی محتوا» (Sync)** می‌رود و دکمه **Pull / Sync** را می‌زند تا سوال بلافاصله در سامانه ظاهر شود.

## ۳. استاندارد نوشتن صورت سوال و تست‌کیس (۲ الگوی اصلی پایتون)

### الف) ساختار استاندارد `question.html`
- خط اول را با استایل مشترک درس شروع کنید (در صورت وجود `bp-theme.css` در `clientFilesCourse/`):
  ```html
  <link rel="stylesheet" href="{{options.client_files_course_url}}/bp-theme.css">
  ```
- روی `<pl-file-editor>` همیشه این دو ویژگی را قرار دهید:
  - `normalize-to-ascii="true"` ← کاراکترهای فارسی/عربی اشتباهی (مثل نیم‌فاصله یا گیومه کج) را خودکار قبل از اجرا اصلاح می‌کند.
  - `source-file-name="tests/initial_code.py"` ← کد اولیه را از فایل می‌خواند.
- برای راهنمایی آموزشی مرحله‌ای بدون لو دادن پاسخ، از `<pl-hidden-hints>` استفاده کنید تا پس از چند تلاش ناموفق باز شود:
  ```html
  <pl-hidden-hints>
    <pl-hint show-after-submission="2" hint-name="💡 راهنمایی">
      <p class="mb-0">متن راهنمایی برای دانشجو...</p>
    </pl-hint>
  </pl-hidden-hints>
  ```
- برای یادداشت‌های داخلی TAها در `question.html` به‌جای `<!-- ... -->` (که در سورس صفحه دیده می‌شود) از کامنت Mustache یعنی `{{! یادداشت محرمانه TA }}` استفاده کنید.

### ب) نوشتن تست‌های الگوی `stdin / stdout` (ورودی و خروجی استاندارد)
در فایل `tests/test_student.py` از تابع آماده `_run_io_case(stdin_data)` که در قالب `template/bp-python-stdin-stdout` قرار داده شده استفاده کنید. برای هر تست، یک تابع با دکوریتور `@pytest.mark.grading_data` بنویسید:

```python
@pytest.mark.grading_data(name="تست عمومی ۱: ورودی عادی (5 و 10)", points=1)
def test_public_basic() -> None:
    out = _run_io_case("5\n10\n")
    assert out == "15", f"خروجی مورد انتظار: 15 | خروجی شما: {out}"

@pytest.mark.grading_data(name="تست مرزی ۱: عدد صفر و منفی", points=1)
def test_edge_zero_neg() -> None:
    out = _run_io_case("0\n-4\n")
    assert out == "-4", f"خروجی مورد انتظار: -4 | خروجی شما: {out}"
```
- **نکته مهم برای دانشجویان:** همیشه در صورت سوال تذکر دهید که داخل `input()` هیچ متن راهنمایی مثل `input("Enter n: ")` ننویسند، چون وارد `stdout` می‌شود و مقایسه خروجی را خراب می‌کند.

### ج) نوشتن تست‌های الگوی تابع (`def` با `pytest`)
در قالب `template/bp-python-pytest`، تابع دانشجو از طریق `sandbox.query_function("func_name", arg1, arg2)` به‌صورت ایمن صدا زده می‌شود:
```python
@pytest.mark.grading_data(name="تست مرزی: لیست خالی", points=1)
def test_empty(sandbox: StudentFixture) -> None:
    res = sandbox.query_function("my_func", [])
    assert res == 0, f"برای لیست خالی خروجی 0 انتظار می‌رفت، خروجی شما: {res}"
```

## ۴. قرار دادن سوالات در تمرین یا آزمون و انتشار برای دانشجویان

بعد از اینکه سوالات در بانک سوالات آماده و تست شدند، آن‌ها را در یک ارزیابی (`Assessment`) قرار می‌دهید:

1. در پوشه `courseInstances/<instance>/assessments/` یک پوشه جدید بسازید (مثلاً `hw02-strings/infoAssessment.json`) یا از پنل وب در بخش **«تکالیف و آزمون‌ها»** اضافه کنید.
2. **انتخاب نوع ارزیابی (`type` — بعد از ساخت قابل تغییر نیست):**
   - **`"Homework"` (تمرین هفتگی):** تلاش نامحدود بدون جریمه، یادگیری تسلط‌محور، نمایش عنوان سوال.
   - **`"Exam"` (کوییز / امتحان زمان‌دار):** تعداد تلاش محدود با امتیاز نزولی (مثلاً `autoPoints: [10, 7, 4]`)، تایمر، تعهدنامه (`requireHonorCode: true`)، مخفی کردن عنوان سوالات، و مخفی کردن سوالات پس از پایان امتحان.
3. **تنظیم زمان‌بندی و ددلاین‌ها (`accessControl` v2):**
   ```json
   "accessControl": [
     {
       "beforeRelease": { "listed": true },
       "dateControl": {
         "release": { "date": "2026-12-10T00:00:00" },
         "due": { "date": "2026-12-20T23:59:59", "credit": 100 },
         "lateDeadlines": [
           { "date": "2026-12-22T23:59:59", "credit": 80 },
           { "date": "2026-12-24T23:59:59", "credit": 50 }
         ],
         "afterLastDeadline": { "allowSubmissions": true, "credit": 0 }
       }
     }
   ]
   ```
   - برای **تمدید اختصاصی** یک دانشجو یا یک گروه (مثل برچسب `Extended-Time`)، نیازی به دستکاری JSON نیست؛ از تب **«دسترسی / Access»** داخل همان تمرین، یک Override اضافه کنید.
4. **تنظیمات پیشنهادی روی تمرین‌های کدنویسی:**
   - `"gradeRateMinutes": 0.5` (فاصله ۳۰ ثانیه‌ای بین ارسال‌ها برای جلوگیری از اسپم صف داوری داکر)
   - `"maxBonusPoints": 10` (در صورت وجود سوال امتیازی)
5. **تست قبل از انتشار با «نمای دانشجو»:**
   - از منوی بالای صفحه روی نام خود کلیک کنید و به **«تنظیمات پیشرفته هویت و نقش»** بروید، نقش موثر را به دانشجو و تاریخ موثر را به زمان انتشار تغییر دهید تا دقیقاً تجربه دانشجو را بررسی کنید.

## ۵. راهنمای TAهای تصحیح، پشتیبانی و مدیریت کلاس

### الف) عضویت و گروه‌بندی دانشجویان در دوره
- کد ثبت‌نام یا لینک مستقیم دعوت دوره را از بخش **«تنظیمات ترم»** در اختیار دانشجویان بگذارید.
- دانشجویان در صفحه ورود ثبت‌نام می‌کنند (**وارد کردن شماره دانشجویی در ثبت‌نام اجباری است**) و با کد دوره عضو می‌شوند.
- از بخش **«دانشجویان دوره ← برچسب‌ها (Labels)»** می‌توانید دانشجویان را بین گروه‌های TA (مثلاً `TA-Group-1` تا `TA-Group-10`) دسته‌بندی کنید.

### ب) تصحیح دستی (Manual Grading) و تقسیم کار بین تیم TA
برای سوالاتی که `manualPoints` دارند (مثل بخش توضیح الگوریتم یا پروژه):
1. وارد تمرین شوید و به تب **«تصحیح دستی / Manual Grading»** بروید.
2. اول روی **Rubric** کلیک کنید و معیارهای نمره‌دهی (مثبت یا کسر نمره + توضیحات) را تعریف کنید تا همه TAها با معیار یکسان نمره بدهند.
3. برای **تقسیم خودکار و مساوی پاسخ‌ها بین TAها**: روی آیکون مداد کنار تعداد پاسخ‌های تخصیص‌داده‌نشده کلیک کنید و لیست TAهای تصحیح‌کننده را انتخاب کنید — سامانه پاسخ‌ها را به‌طور یکنواخت و با **ترتیب تصادفی ضدسوگیری** بین آن‌ها تقسیم می‌کند.
4. هر TA دکمه **Grade next submission** را می‌زند و با کلیدهای عددی `1` تا `0` روی کیبورد سریع آیتم‌های Rubric را اعمال می‌کند. *(اگر وسط کار امتیاز یکی از بندهای Rubric عوض شود، نمره تمام برگه‌های تصحیح‌شده قبلی به‌صورت خودکار بازمحاسبه می‌شود.)*

### پ) بررسی اشکالات (Issues)، دفتر نمرات و Regrade
- **گزارش اشکالات (`Issues`):** دانشجویان می‌توانند روی هر سوال اشکال گزارش کنند؛ سرگروه‌های TA روزانه این تب را چک و پس از اصلاح، Issue را ببندند.
- **دفتر نمرات (`Gradebook`):** شامل نمره هر سری، درصد کل و شماره دانشجویی (`UIN`) با قابلیت دانلود CSV برای ورود به سیستم آموزشی دانشگاه.
- **بازنگری نمره (`Regrade`):** اگر بعد از شروع تمرین متوجه باگ جدی در یک سوال شدید، در `infoAssessment.json` روی آن سوال `"forceMaxPoints": true` بگذارید، Sync کنید و در تب **Students ← Actions ← Regrade** نمره کامل آن سوال را اعمال کنید.
- **ردیابی تقلب در امتحانات:** در تب **Students ← Details ← Log** هر دانشجو، تغییرات IP، سشن و مرورگر (Fingerprint) ثبت می‌شود.

## ۶. چک‌لیست کنترل کیفیت قبل از انتشار هر سری

- [ ] **UUID یکتا:** برای هر سوال جدید یک `uuid` جدید ساخته شده و با هیچ سوال دیگری تکراری نیست.
- [ ] **استایل و فارسی‌سازی:** استایل راست‌به‌چپ لود شده، متن سوال شفاف و جدول نمونه‌ها خوانا هستند.
- [ ] **`normalize-to-ascii="true"`** روی `<pl-file-editor>` قرار داده شده است.
- [ ] **تست‌های مرزی:** علاوه بر نمونه صورت سوال، حداقل ۲ تست مرزی (صفر، عدد منفی، رشته خالی، مقادیر خیلی بزرگ یا نقاط مرزی شرط‌ها) در `test_student.py` نوشته شده است.
- [ ] **تست مثبت و منفی در پیش‌نمایش:** کد اولیه (`initial_code.py`) نمره `0%` و کد مرجع صحیح نمره `100%` می‌گیرد.
- [ ] **نکته LaTeX در Mustache:** اگر در `question.html` فرمول LaTeX همراه با `{{params.x}}` دارید، بین `{` و `{{` فاصله بگذارید (مثل `\frac{ {{params.a}} }{ {{params.b}} }`) تا سه آکولاد `{{{` نشود.
- [ ] **بدون خطای Sync:** پس از زدن **همگام‌سازی محتوا**، هیچ خطا یا هشداری روی درس یا سوال نمایش داده نمی‌شود.
